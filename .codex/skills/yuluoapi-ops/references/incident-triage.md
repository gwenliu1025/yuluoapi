# 生产故障排查

## 502 与上游失败

按同一请求时间窗建立证据链：

1. 应用健康、运行版本、镜像与提交。
2. 应用日志和 `ops_error_logs` 中的下游状态、上游状态、错误分类、endpoint 与账号 ID。
3. `usage_logs` 是否生成、是否成功计费，以及失败发生在转发前还是上游响应后。
4. API Key 分组、账号分组、调度候选与实际选中账号的映射。
5. 账号 Base URL、代理、余额/额度、临时不可调度和限流状态。
6. 上游响应与下游映射的代码路径；下游 502 不等于本地网关崩溃。

只记录短预览、哈希和必要字段；请求体、响应体、签名、Token、Cookie 和凭据不进入证据文档。

## 计费与模型元数据

- 区分用户消费、上游账号成本、倍率和利润，先确认字段 owner 再判断异常。
- 模型元数据警告与请求失败分开判断；缺失元数据可能只影响展示或估算。
- 账号余额不足、上游 401/403/429/5xx、代理失败和本地调度失败分别归类，不用一个状态替代另一个。
- 修复后同时验证原失败请求、正常主路径和直接消费者；禁止通过放宽断言或跳过测试制造通过。
